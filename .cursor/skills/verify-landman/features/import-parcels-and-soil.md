# Import parcels and soil

`./landman` with no arguments reads `DATABASE_URL` and runs `union.gis.parcels`, then `union.gis.soil`, then `union.soil.screening`. The parcel job upserts accepted parcels and their kept sale slots. It prints fetch progress on stderr and prints nothing on stdout. An invalid record is quarantined, that parcel id is left unchanged, and the job outcome is `success_with_quarantine`. That outcome stops the later jobs. The soil job stores soil. The screening job screens that committed set. An error, or any outcome other than `success`, stops the later jobs. `./landman import` is not a command. It exits 1 with a usage error before it opens the database. `./landman reprocess union.gis.parcels --limit N` repairs pending parcel records when `N` is an integer from 1 through 100.

## Sub-features

- `import-build` produces the `./landman` binary.
- `import-run` writes parcels and soil, then runs screening inside one 10 minute deadline.
- `import-stdout` stays empty while stderr shows the parcel fetch.
- `import-jobs` records `job_attempts` for `union.gis.parcels`, `union.gis.soil`, and `union.soil.screening`. A clean parcel attempt is `attempt_kind` `full_scan` and outcome `success`.
- `import-verdict` runs `classify` and writes `drive-outcome.json`.
- `import-usage` rejects `./landman import` and any other unknown argument.
- `import-reprocess` rejects a limit outside 1 through 100 before the database opens. A clean repair of an empty pending set screens stored soil and does not fetch county parcels.

## How to get to it (user POV)

- From the repo root, run `make build`, then run `./landman` with `DATABASE_URL` set to the verify database host URL in `SKILL.md`.
- `./landman run union.gis.parcels` fetches parcels and then screens stored soil when the parcel outcome is `success`. It does not fetch county soil. `success_with_quarantine` does not screen. `./landman run union.gis.soil` fetches soil and then screens when the soil outcome is `success`. It does not fetch parcels. `./landman run union.soil.screening` only screens the stored set.
- `./landman reprocess union.gis.parcels --limit N` repairs at most `N` pending parcel records, then screens stored soil when the repair outcome is `success`. It does not fetch county soil. The limit check happens before the database opens.
- `make run` is the operator shortcut. It loads `.env` when that file exists. Verification does not use it.

## Driving it with make and the landman binary

Preconditions:

- The verify database launch in `SKILL.md` has exited 0, including `check-loaded`.
- Database doctor and CLI doctor have passed for this container.
- No other `./landman` process is running.
- `SOIL_SCREENING_MAX_AGE` is unset, or it is a valid positive Go duration. The default freshness interval is 30 days. An explicit run still refreshes USDA evidence.

- Run `make build`. Exit code 0 and `./landman` exists.
- Treat the `check-loaded` census as the reset check. Stdout includes `census parcels=` and a `census parcel` line for `07102010` and for `07102051`, then `loaded: ok`. Do not start `./landman` until that command exits 0.
- Run `probe` with `--evidence "$EVIDENCE"`, using the helper path in `SKILL.md`. Exit code 0. `page-timings.json` is in that directory. A slow data page still exits 0 when both metadata calls returned HTTP 200.
- Run `DATABASE_URL="$HOST_DATABASE_URL" ./landman`, capturing stdout, stderr, and the exit code under `artifacts/verify/$RUN_ID/`. Keep the process until it exits.
- Read parcel progress on stderr. It contains `[union_county_gis] Total parcels to fetch: ` with a count greater than 0, then `[union_county_gis] Batch size: 2000, Total batches: `, then `[union_county_gis] Fetch complete:`. Those lines start during the parcel job, before the soil fetch. The soil fetch itself prints nothing.
- Read stdout. It is empty. The parcel job does not print a vacant-count summary.
- Run `classify` with the flags in `SKILL.md` after the process exits, including when that exit is not 0. A clean import exits 0 and `classify` prints `pass`. `drive-outcome.json` then records `seededSales` and `fullImport` as `met`. The county parcel count is greater than the seed parcel count. Soil polygons and overlaps for `union` and `union_county_gis` are greater than the seed insert counts. `job_attempts` has `attempt_kind` `full_scan` and outcome `success` for `union.gis.parcels`, for `union.gis.soil`, and for `union.soil.screening`. `soil_screening_heads` has one row for that county and source. `soil_parcel_assessments` has the same count as the imported county parcels. Do not query a county-wide `parcel_sales` total. The import replaces the seed soil rows with the county soil set. `classify` treats the parcel scan as published when that parcel row is `full_scan` and the outcome is `success` or `success_with_quarantine`.
- Keep `import.stdout.txt`, `import.stderr.txt`, `import.exit.txt`, `page-timings.json`, and `drive-outcome.json`. On `pass`, the exit file contains `0`. Stderr for that success does not contain `import parcels:`, `required union.gis.parcels:`, or `context deadline exceeded`.
- Run `./landman import` with no `DATABASE_URL`. Exit code 1. Stdout is empty. Stderr contains `usage: landman [schedule | run <union.gis.parcels|union.gis.soil|union.soil.screening> | reprocess union.gis.parcels --limit N]`.
- Run `./landman reprocess union.gis.parcels --limit 0` with no `DATABASE_URL`. Exit code 1. Stdout is empty. Stderr contains `reprocess limit must be between 1 and 100`. The process does not open the database and does not fetch the county.
- Do not run `./landman run union.gis.parcels` or `./landman run union.gis.soil` in the same pass as bare `./landman`. Each of those commands fetches that county layer again. One pass has one county parcel drive, and that drive is bare `./landman`.
- After `classify`, count pending parcel quarantine rows. When that count is 0, run `DATABASE_URL="$HOST_DATABASE_URL" ./landman reprocess union.gis.parcels --limit 1`. Exit code 0. Stderr has no `[union_county_gis]` line. The command screens stored soil and does not fetch county parcels. When the count is greater than 0, do not run that command in this pass. A pending row would fetch the county again. Record the limit check as the reprocess proof and name the pending count as the reason the empty-repair path was not driven.

## Gotchas

- This drive hits the live county ArcGIS service and the USDA Soil Data Access tabular endpoint. There is no dry-run flag. Do not run two imports at once. The second run exits non-zero with `required union.gis.parcels did not complete cleanly: skipped_overlap`.
- The soil fetch prints nothing. It runs after `Fetch complete:`. The parcel job prints nothing on stdout. The first `[union_county_gis]` line is the parcel job. After `Fetch complete:`, soil storage and screening also print nothing. The process can stay quiet for minutes. Wait for the exit code.
- The deadline is 10 minutes for parcel import, soil fetch, soil storage, and screening. Parcel batch size is 2000, at about one request per second. A deadline failure exits non-zero. Stderr then contains `required union.gis.parcels:`, `required union.gis.soil:`, or `required union.soil.screening:`. A parcel or fetch failure also contains `import parcels:` or `fetch soil polygons:`. A soil store failure is `required union.gis.soil:`. A deadline failure contains `context deadline exceeded` or `rate: Wait(n=1) would exceed context deadline`. Do not stop after the first parcel batch, or after `Fetch complete:`, and call the drive verified.
- `classify` prints `inconclusive: county-source-slow` and the helper exits 2 when stderr contains `context deadline exceeded` or `rate: Wait(n=1) would exceed context deadline`, and the county was slow. Slow means metadata returned HTTP 200 within 5 seconds and a timed probe data page took at least 15 seconds or timed out. Batch log gaps include translation and database writes. They do not identify county request time. Without that deadline text, a non-zero exit is `fail`. That inconclusive verdict is not a pass. `go run` turns the helper exit into shell exit 1 and prints `exit status 2` on stderr. Read the verdict line. If no full parcel scan published, `seededSales` is `not-run` and `fullImport` is `missed`. If a full scan published and the seeded slots match, `seededSales` is `met` and `fullImport` is `missed` when the process exit is not 0.
- Each county request uses a 30 second client timeout and waits 15 seconds for response headers. The USDA name lookup uses a 5 second limit and can fail open while the parent context is still active. Screening uses the default HTTP client. A stalled county request fails the drive while the 10 minute deadline is still running.
- A short final page is valid when its length is the remainder under 2000. Any other short page fails. Stderr contains `import parcels:` and `count mismatch: page <n> got <x> want <y>`. The page number in that error is 0-based. `Batch <i>/<total> complete` is 1-based. A summed-page mismatch uses `count mismatch: fetched <got> want <want>`, also wrapped by `import parcels:`.
- Likely vacant means numeric zero `YEARBLT` or numeric zero `SQFT`. A zero improvement value, or a land type that contains `RURAL ACREAGE TRACT`, does not by itself mark a parcel vacant. An empty `PID` is stored with `likely_vacant` false. The command does not print a vacant-feature count.
- `make run` rebuilds before it executes, and Make exports `.env`. That URL is the operator database. Use `./landman` with `HOST_DATABASE_URL`.
- Fatal text on stderr includes `create GIS source:`, `fetch soil polygons:`, `import parcels:`, `union repair:`, `required union.gis.parcels:`, `required union.gis.soil:`, `required union.soil.screening:`, `required union.gis.parcels did not complete cleanly:`, `required union.gis.soil did not complete cleanly:`, `required union.soil.screening did not complete cleanly:`, `success_with_quarantine`, `invalid SOIL_SCREENING_MAX_AGE`, `connect for derived refresh exclusion:`, and `wait for derived refresh exclusion:`. The process exits non-zero. A bad `DATABASE_URL` or a job-runner error reaches `log.Fatal` with no GIS prefix. A bad reprocess limit prints `reprocess limit must be between 1 and 100` and does not print the usage line.
- `./landman run union.gis.parcels` or `./landman run union.soil.screening` with no stored soil set records `pending` for `union.soil.screening` and exits non-zero. The parcel attempt can already be `success`. Bare `./landman` stores soil before screening, so the first full run does not take that path.
- A screening overlap is retried until the attempt succeeds or the deadline fires. The deadline text is `required union.soil.screening:`.
- Screening, assessment, and measurements print nothing. Their operator-visible failure text is `required union.soil.screening:`. `soil_measurements` may be empty when USDA returns no measurement rows. An exit of 0 still requires the screening job outcome `success` and a `soil_screening_heads` row.
- `SavePart` upserts each parcel and its kept slots on the import transaction and deletes omitted sequences. `SaveSales` alone does not delete. Compare sale slots through `classify`, which reads only the seed parcel ids. Do not prove this feature by inserting sales from a scratch program.
- The import commits accepted parcel shapes before the soil job and screening. A later failure can leave county parcel rows behind, with exit code non-zero and empty stdout. `classify` then prints `inconclusive: county-source-slow` only when the deadline text is present, a full parcel scan published, the seeded slots match, and the county was slow by the rule above. Any other non-zero exit after that commit is `fail`.
