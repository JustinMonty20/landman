# Union vacancy evidence ingestion

## Scope

Capture Union Structures layer 171 and Assessed Value layer 0 as separate sources. Use the [shared ingestion contract](shared-ingestion.md) and the [vacancy evidence plan](vacancy-building-tax-evidence.md). Use the existing application and county request controls. Do not add automatic schedules in this change. Do not run a live full-county import without approval.

## Capture and replay

- Register each manual job with `jobs.Runner.Run`. Use the existing county client, rate limit, and host exclusion. Keep the two source captures independent.
- Retain bounded exact response bytes and request metadata with `ingest.Engine`. Raw SHA-256 identifies each response. A separate versioned canonical multiset fingerprint compares normalized rows with multiplicities against the latest generation. Reversions A to B to A publish A again. Replay can correct its own latest generation but must not contact the county or replace newer evidence.
- Preserve repeated assessment rows in the raw capture. Do not assume `OBJECTID` is unique in layer 0. Reject malformed or count-mismatched observations. A failed refresh must not replace the latest accepted bounded observation. The runner's generic `full_scan` attempt label is not a completeness assertion; `coverage_verified` stays false.
- **Live gate.** Structures capture accepts at most 250,000 features in 2,000-row pages ordered by `OBJECTID ASC`, reconciled against unique numeric `returnIdsOnly` membership lists before and after paging, with count receipts at both ends. Page OIDs must match the sorted source ID list exactly. A full nonfinal Structures page may set `exceededTransferLimit=true` when its OIDs match that list. Reject a short page, a flagged final page, any missing or repeated ID, changed membership, or count drift. The saved county page at offset 0 had 2,000 of 2,000 expected records, matched the first 2,000 of 163,500 unique source IDs, and set the flag. This supports the bounded nonfinal-page rule, but does not verify a complete live capture. These checks detect observed drift but do not prove a snapshot or source-wide completeness. Assessed Value partitions the nonnegative signed 64-bit `OBJECTID` domain `[0, 9223372036854775807]` into disjoint inclusive ranges using exact `OBJECTID >= low AND OBJECTID <= high` predicates and count-guided splits. Every leaf retains at most 2,000 rows, including repeated IDs and exact duplicate rows. An indivisible over-limit ID group rejects. New captures retain a revision-tagged global count, then count the root and both children of each branch exactly once before admission. The complete count tree includes empty leaves and admits paging only when the census plus two receipts per populated leaf and one final global count fits the 2,048 receipt limit. Empty leaves have no page or post-page count. Capture compares global and root counts, each branch's child sum, each populated leaf's retained row count and post-page count, and the final global count. New live capture and offline replay interpret the same count-first grammar; untagged successful range tapes and two-receipt legacy observations retain their legacy parsers. Replay checks the exact receipt sequence, predicates, exhaustive partition tree, summed counts, and every row's membership. Count agreement detects observed drift, not a snapshot. Never offset-page a nonunique ID or infer countywide completeness from count checks. Manual `full_scan` remains a runner attempt label, not a verified scan. Countywide assessment capture and real tiers remain blocked pending live verification of exact range and count query support with repeated rows, source identity, snapshot behavior, transfer-limit, repeat-scan, terms, dates and coverage. Fixtures cannot establish those live properties.
- **Response limits.** HTTP refusal bodies, malformed JSON and invalid CRS pages are retained when bounded response bytes are available. Transport failures with no body have nothing to retain. Responses over 32 MiB are truncated to 32 MiB plus one byte and rejected; artifact-store limits may prevent retaining even that prefix.

## Likely-vacant filters

- Join the sources to parcels independently. Compare footprint polygons with the full parcel polygon. Positive-area overlap counts even without full containment. Edge contact does not count. Keep `PIN_Num` as source evidence. Flag a mismatch between the reported parcel number and spatial overlap.
- Use `market_building` only from an applicable `AV` (Appraisal) row. Do not use `PY` (Prior Year), `market_land`, or a higher year or amount as a substitute. Treat identical duplicate rows as one observation for selection. Keep missing values, conflicting applicable rows, and an unverified appraisal year unknown.
- Show **strong candidate** only for an explicit zero building value, verified footprint coverage with no positive-area overlap, and parcel facts that do not report a structure. Show **conflict** when comparable sources disagree. Show **review** when building evidence needs manual review. Show **unknown** if required data, coverage, or parcel identity cannot be verified. Tax debt and imagery do not change the tier.
- Keep `likely_vacant` active until both sources and parcel matching pass validation, real tiers are backfilled, and all readers can use the new tiers. Do not edit migration `000038` or enable real tiers from unverified captures.

## Remaining county-scale measurement
- Structures capture and offline replay reject more than 256 MiB of combined response bytes; each response also remains limited to 32 MiB. The 250,000-row count gate and job deadline still apply. The aggregate budget limits retained bytes, not peak heap or database publication time. An over-budget live capture is rejected, never downgraded to the older two-receipt protocol.
- Before countywide use, measure actual county Structures count, aggregate response bytes, peak heap during normalization and fingerprinting, publication duration, deadline margin, ID reconciliation stability, and repeat-scan coverage under approved live access. Fixture tests do not establish these measurements. Assessment is bounded to 500,000 total observed rows, 2,000 rows per leaf, 2,048 total receipts, 32 MiB per response, and 256 MiB aggregate response bytes. A county count receipt reported 490,180 rows. A bounded 208-row source range returned 49,887 bytes, which projects to about 118 MB of row responses at that row size; the estimate does not verify the full capture. Assessed-value capture has a three-hour deadline in both the standalone and combined manual commands. Other combined jobs and scheduled source jobs retain their ten-minute deadlines. County-scale duration remains unverified. Receipt count bounds work but not peak heap or publication time. Outside-domain rows and indivisible oversized ranges reject. Live county use requires approved query-capability and repeat-scan measurements; local fixtures only establish rejection and replay behavior.
- Two-receipt historical Structures captures may replay offline with their original bounded single-page gates and HTTP audit checks. Their published provenance explicitly says source-ID membership was not reconciled. New live fetches always use paged, reconciled Structures capture.
