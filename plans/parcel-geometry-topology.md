# Parcel geometry topology fix

**Scope.** Fix the Union layer 215 ArcGIS ring translation used by the existing parcel importer. No change to fetch, parcel identity, vacancy classification, migrations, sales, or soil ingestion. Do not delete parcels, discard rings, or call `ST_MakeValid`.

**Cause.** ArcGIS rings may contain multiple clockwise exterior boundaries in one feature. `geometryShape` flattened all rings into one PostGIS Polygon, implicitly treating every ring after the first as a hole. Captured live OBJECTID 182363 / PID 03042001A contains two clockwise exterior rings. The flattened polygon reports `Hole lies outside shell` in an isolated PostGIS database; the full-import `ST_Union` then raises `TopologyException: unable to assign free hole to a shell` near the same Union location.

**Correction.** Preserve each clockwise ArcGIS exterior ring as a separate polygon in one geometry; associate counterclockwise interior rings with the smallest containing shell. A feature with one shell remains Polygon; one with multiple shells becomes MultiPolygon. A hole without a shell produces no shape, causing the existing ShapeWriter to reject the part and roll back the import. Continue staging parts and dissolving by PID inside one transaction, without deleting or omitting any part. Do not repair unrelated invalid source rings by altering their boundaries.

**Verification.** Add a captured feature fixture and assert its translation retains two shells and that ShapeWriter commits a valid two-part geometry in isolated PostGIS. Cover hole association and rejection when no exterior shell exists. Run `go test -race ./...` and `go test -race -tags postgres ./internal/parcelstore/...` with a disposable migrated PostGIS DB. Run the complete live layer 215 import to that DB and assert all 118,202 source features produce 117,983 stored parcels, with no null shapes, and that PID 03042001A remains two parts. No merge; open a ready fix PR.

**Source limitations.** Other Union source geometries may contain self-touching rings. This fix does not silently repair or drop those records. PostGIS `ST_Union` currently accepts some invalid single-part rings without changing their geometry; monitor these separately rather than widening this topology correction.
