# Parcel follow-up tasks: queue-only stub

**Delivery boundary.** This implements private follow-up tasks and a real PostgreSQL reminder-intent queue. It does not provision EventBridge, call AWS, send SMS, collect phone numbers, or complete V1 SMS delivery. Tasks are not owner outreach. The buyer's own message is private and never included in API logs.

**Workflow.** Favorite a parcel, then use Follow-up tasks in its selected parcel details to create a message and due time. `/leads` shows the paged upcoming and overdue queue with parcel links. Editing or snoozing a task creates another schedule version; it cancels only a still-queued older version. Completing a task does not submit or simulate an SMS. Canceling, excluding the lead, or removing the favorite cancels queued intent in the same database transaction. Restoring a favorite or lead does not reactivate canceled intent. Explicitly reschedule to create a new version. A task already simulated remains open until completed or canceled. The pane deliberately says EventBridge and SMS are stubbed.

**Trigger.** On a due, account-owned, active, non-excluded task, press **Simulate SMS (not sent)** in its parcel pane or `/leads`. This calls `POST /api/me/favorites/{parcel_id}/tasks/{task_id}/stub` with `{"revision": N}`. The authenticated API locks the account and task, rechecks current status, version, favorite and exclusion, and atomically transitions the current queued row to `stubbed` (or `missed` if more than one hour past due). It logs `sms-stubbed-not-sent` or `sms-missed-not-sent` with only stable task/parcel IDs, due UTC and version. It never contacts AWS or a carrier. Duplicate or stale calls return 409; an early call returns 400. There is **no automatic trigger**, no timer, no scheduled consumer, and no silent consumption of due intents. A queued row persists after due time until explicit simulation, cancellation or rescheduling. Missed simulation leaves task open for explicit reschedule. Browser clicks operate only on the authenticated account's tasks.

**API.** `POST /api/me/favorites/{parcel_id}/tasks` creates with a client UUID idempotency token and `{id,message,due_at,timezone}`. `due_at` is an RFC3339 local timestamp with explicit numeric offset and `timezone` an IANA identifier; server rejects an offset inconsistent with the zone, including nonexistent DST hours. Ambiguous DST hours require choosing one of two offsets. The server stores UTC. `POST /api/me/favorites/{parcel_id}/tasks/{task_id}/reschedule` takes `{revision,message,due_at,timezone}` and creates an explicit new version; `/complete`, `/cancel`, `/stub` take `{revision}`. `GET /api/me/crm/tasks` and `GET /api/me/favorites/{parcel_id}/tasks` use a bounded cursor (default 20, maximum 50), due-time ordering and only open tasks. `GET /api/me/favorites/{parcel_id}/tasks/{task_id}` reads task status even after completion. All writes require authenticated exact-origin JSON, and guessed foreign IDs do not disclose tasks. API log schedule/cancel entries are operational stub notices, not a durable audit trail; the database queue is authoritative even if process logging fails after commit.

**Message limit.** The editor and server enforce one GSM-7 160-septet segment (extension characters use two septets), or 70 UTF-16 units for Unicode (supplementary characters use two). No text is added, truncated, or actually sent. This limit has not been verified against a selected AWS SMS product. Production delivery still requires verified buyer US destination and consent, sender registration and opt-out requirements, selected AWS product/runtime, claim/retry/uncertain-acceptance design, provider tests and due-time measurements. None is implied by simulated status.

**Verification boundary.** Use an isolated, migrated disposable PostGIS database for `go test -tags postgres -race ./internal/parcelcrm`; set `CRM_TEST_DATABASE_URL` explicitly to its URL. Browser evidence uses Playwright route fixtures and does not verify the live API or real SMS. Do not run the tests against an operator or county database.
